# 対戦レートと人間の着手一致率の描画

`plot_rating_vs_human_match.py`は、20261008の30モデルの集計済み`report_data.json`を読み込み、6種類の図をPNG・SVGで出力します。レート対一致率の図では、保存済みのEloブートストラップと局面別予測から、両軸を加味した95%同時信頼帯を計算します。学習・推論・対戦を再実行する必要はありません。

## 実行

このフォルダの`run_rating_vs_human_match.bat`を実行してください。既定ではワークスペースの`experiment_bat/20261008/report_data.json`を読み込み、[output/20261008](output/20261008)へ保存します。ラベル編集用BATも同じ入力と出力先を使います。実行時のカレントディレクトリには依存しません。

Pythonから実行する場合は、次のコマンドをこのフォルダで使います。

```powershell
python .\plot_rating_vs_human_match.py
```

必要なライブラリは`numpy`（1.22以上）と`matplotlib`です。BATでは`POLICY_PYTHON`にPython実行ファイルを指定できます。自動実行で終了時のキー入力待ちを省く場合は、`POLICY_NO_PAUSE=1`を設定してください。

別の実験の集計JSONを描画するときは、入力と出力先を指定します。

```powershell
python .\plot_rating_vs_human_match.py `
  --input ".\input\report_data.json" `
  --output-dir ".\output\my_experiment"
```

レートと一致率の図だけを出力することもできます。以下のオプションはBATにも渡せます。

```powershell
.\run_rating_vs_human_match.bat `
  --figures elo_vs_agreement mistake_elo_vs_agreement `
  --formats png svg
```

| 系列 | 色 | 図中の記号 |

| Edax | 青 `#2468B4` | D：レベル |
| 提案手法：通常モデルとEgaroucid L21の融合 | 赤 `#D62728` | α＝0.0〜1.0 |
| 提案手法：石損モデルAと通常モデルの融合 | 赤 `#D62728` | α＝1.0〜2.0 |
| 提案手法：石損モデルBと石損モデルAの融合 | 赤 `#D62728` | α＝2.0〜3.0 |
| ランダム | 灰 `#747C85` | R |

石損モデルAは学習時に`（石損＋1）²`、石損モデルBは`2^(石損/2)`の重みを用いたモデルです。図中のαは論文と同じ0〜3の通し表記で、0.2刻みです。入力JSONの系列内係数は変更せず、通常モデル系列はそのまま、石損A系列は1を、石損B系列は2を加えて表示します。

単独モデルの出力には`α=0.0（Egaroucid L21）`、`α=1.0（通常モデル）`、`α=2.0（石損モデルA）`、`α=3.0（石損モデルB）`とモデル名も併記します。全モデルを並べる図と散布図では、共有端点を一度だけ赤で表示します。Egaroucidの閾値パネルでは、同じ端点を従来のE21として緑で表示します。

EgaroucidとEdaxは各7レベル（1・3・5・9・13・17・21）、提案手法は15モデル、ランダムは1モデルで、計30モデルです。過去の23モデルのJSONも`--input`で指定でき、旧データの提案手法は赤でα＝0〜2と表示します。同時信頼帯に必要な元データの指定がない旧JSONでは、`--ci-mode pointwise`を付けてください。

## 95%同時信頼帯

既定では、`elo_vs_agreement`と`mistake_elo_vs_agreement`の半透明の帯に、レート・着手一致率の両方を加味した95%同時信頼帯を表示します。対象は条件ごとの各系列の折れ線全体です。Egaroucid、Edax、提案手法を別々に計算し、提案手法はα＝0〜3の全区間を一つの系列にまとめます。共有端点は一度だけ数えます。ランダムには、1点の両軸を対象とする95%信頼領域を表示します。

帯はブートストラップによる近似的な区間です。全系列・全条件をまとめて95%で覆うものではありません。また、推定対象は「評価済みモデルの真の座標を、レベルまたはαの順に直線で接続した折れ線」です。未評価のαやレベルでの実際の性能は、この保証の対象に含めません。

### 計算方法

`simultaneous_bands.py`で、最大標準化偏差によるブートストラップ（sup-t型）を計算します。

1. Eloは、保存済みの20,000回の再推定値を使います。対戦組ごとに先後2局のセットを再抽出した結果で、同じ反復の全モデルをまとめて使うことでモデル間の相関を保ちます。
2. 一致率は、各条件に該当する評価局面を復元抽出して、同じく20,000回再計算します。全モデルに同じ抽出局面を使います。実装では全モデルの一致・不一致パターンをまとめ、多項分布でその出現数を抽出します。これは局面ごとの復元抽出と同じ分布になり、計算量とメモリを減らせます。
3. 各点・各軸の標準誤差を再推定値から計算します。各反復について、元の点推定値からのずれを標準誤差で割り、その絶対値の最大を系列内の全点・両軸から取ります。その最大値の95パーセンタイルを、系列に共通する係数`c`とします。
4. 各点・各軸に`点推定値 ± c × 標準誤差`の範囲を作ります。一致率は確率の範囲0〜1に制限します。隣り合う点の長方形の領域間を線形補間して、その通過範囲を帯として塗ります。横方向の端まで含め、レートが途中で増減する系列でも元の接続順を保ちます。

標準誤差は各座標の全ブートストラップ標本から一度計算する方式です。反復ごとに標準誤差を再推定する二重ブートストラップは行いません。分位点はNumPyの`method="higher"`で選びます。帯の形は、隣接する長方形の凸包の和集合です。同一系列内の重なりで濃くならないよう、一つのパスとして塗ります。

方法の背景は[Montiel Olea・Plagborg-Møllerによる同時信頼帯の研究](https://www.mikkelpm.com/research/)を参照してください。本スクリプトでは、その最大標準化偏差による補正を両軸の推定値に適用し、補正後の領域を線形補間しています。

### 前提と保存データ

学習済みモデルを固定し、Elo評価と一致率評価の標本抽出を独立とみなします。一致率の保存予測には棋譜IDがないため、再抽出は局面単位です。同一棋譜や重複局面による依存は補正していません。少数の一致しかない条件では、ブートストラップ近似の精度にも限界があります。学習のやり直し、エンジン設定の変更、XOT局面集そのものの不確実性も含みません。

使用するファイルは、入力JSONの`sources`から探します。

- `strength_elo_bootstrap_replicates.csv`：同じ反復における全モデルのElo。
- `wthor_test_100000_predictions.npz`：全体評価の局面別予測と対称性を含む正解集合。
- `mistakes_predictions.npz`：石損評価の局面別予測、正解集合、石損値。

ファイルのSHA-256、モデルID、各条件の局面数・一致率、Eloの保存済み95%区間との一致を検証してから計算します。元ファイルが欠けている場合や集計値と合わない場合は、描画を中止します。計算できないときに従来の帯へ自動的に切り替えることはありません。

出力先の`simultaneous_band_data.json`には、系列・条件ごとの帯の上下限、標準誤差、係数`c`、乱数seed、元ファイルのハッシュ、推定の前提を保存します。`bootstrap_max_coverage`は係数を選んだ標本内での包含率であり、未知の真値に対する被覆率の実測値ではありません。入力・seed・計算法・NumPyバージョンが一致するときは保存値を再利用するため、ラベル編集のたびに再計算する必要はありません。

一致率の乱数seedは既定で614です。変更する場合は、次のように指定します。

```powershell
python .\plot_rating_vs_human_match.py --band-seed 614
```

### 濃さと従来表示

帯は線と同じ色で、不透明度の既定値は15%です。レート対一致率の図では、点のマーカーで推定値を示し、十字の誤差バーは表示しません。モデル別の比較図では、各軸の点ごとの95%区間を引き続き表示します。閾値別の図`threshold_trends`の帯は、一致率の点ごとのWilson区間です。

```powershell
python .\plot_rating_vs_human_match.py --ci-alpha 0.15
```

`0`は完全に透明、`1`は不透明です。以前の`--ci-transparency 0.85`も、`--ci-alpha 0.15`と同じ指定として使えます。

集計済みの区間だけがある旧レポートを描く場合や、従来表示と比べる場合は、明示的に切り替えます。

```powershell
python .\plot_rating_vs_human_match.py --ci-mode pointwise
```

この場合、半透明の帯は一致率の95% Wilson区間を接続したものです。レート方向の不確実性は表示しません。

## タイトル・ラベルなどの文字と位置の変更

`adjust_rating_vs_human_match_labels.bat`を実行すると、6種類すべての図を順に編集できます。レート対一致率の2種類から表示し、一つのウィンドウを閉じると次の図へ進みます。全体10万局面の右隣は、2石以上の石損条件です。レート対一致率の各パネルには全モデルのラベルを表示し、どの点ラベルも個別に動かせます。共有端点は同じモデルなので、各パネルに一つ表示します。

保存済みの位置がないラベルは、点やほかのラベルと重なりにくい位置へ自動配置します。保存済みの位置は優先し、自動配置では動かしません。

1. ラベルをマウスの左ボタンでドラッグして移動します。
2. 文字をダブルクリックすると、表示内容を自由に変更できます。図全体のタイトル、各パネルのタイトル、軸名、凡例、目盛り名、モデル名、数値ラベル、注記が対象です。クリックで選んでから`E`キーを押しても編集できます。
3. `S`または`Ctrl+S`で、文字と点ラベルの位置をJSONへ保存し、PNG・SVGも更新します。
4. `R`で、そのウィンドウを開いたときの文字・位置へ戻します。保存したい場合は再度`S`を押してください。

保存せずウィンドウを閉じた場合は、既存の位置ファイルと画像を変更しません。点から離したラベルには、対応する点への引き出し線が付きます。ツールバーの拡大・移動モード中はラベルをドラッグできないので、調整前にそのモードを解除してください。

通常のBATに`--adjust-labels`を付けても同じ画面を開けます。1種類だけを編集する例です。

```powershell
.\run_rating_vs_human_match.bat --adjust-labels --figures elo_vs_agreement
```

設定は既定で`output/20261008/label_positions.json`へ保存します。点ラベルは`figures`、タイトル・軸名などは`texts`に記録します。図名やパネルの識別子ごとに保存するため、同じ名前の文字でも設定が混ざりません。文字を変更しても、対応するモデルや元データ、目盛りの数値座標は変わりません。次回の通常描画でも、このファイルを自動的に読み込みます。以前の位置ファイルも引き続き読み込めます。

`--label-positions`で別の位置ファイルを指定できます。`--reset-labels`を付けると保存済み位置を無視して既定位置から開きます。編集画面で`S`を押すまでは保存済みファイルを変更しません。新しい位置ファイルはversion 2形式で、`legacy`の旧図専用ファイルとは別です。

同時信頼帯の注記には新しい識別子を付けているため、従来の「Wilson区間」という保存済み注記で上書きされません。点ラベルの位置や、タイトルなどの編集内容は引き続き読み込みます。

編集画面にはQtまたはTkが使えるPythonが必要です。Qtを優先し、使えない場合はTkで起動します。この環境のWindows Python 3.9とQtで動作を確認しています。通常の画像生成にはGUIを使いません。

## 入力JSONの形式

20261008の`report_data.json`と、従来の20261007_2の形式を読み込めます。描画に必要なのは以下の項目です。

- `models`：`model_id`、表示名`model`、短縮名`short`、`group`、`elo`、`elo_low`、`elo_high`、`results`。
- 各モデルの`results`：`dataset`、`positions`、`top1_accuracy`、`top1_ci95_lower`、`top1_ci95_upper`。一致率とその区間は0〜1の値です。
- `datasets`（旧形式は`dataset_counts`）：`dataset`、`label`、`positions`、`minimum_loss`。先頭は全体データで`minimum_loss=null`、以降は石損条件です。
- `series`（旧形式は`series_paths`）：系列名からモデルIDの配列への対応。配列の順序を線の接続順として使います。共有する端点は複数の系列に含められます。
- `sources`：同時信頼帯の計算に使う元ファイルの`path`と`sha256`。`--ci-mode pointwise`では不要です。

30モデルの系列名と`group`は`E`・`D`・`N`・`A`・`B`・`R`です。内部では順に`Egaroucid`、`Edax`、`normal`、`loss_a_normal`、`loss_b_loss_a`、`random`へ対応づけます。これらの正式名と旧形式の`squared_blend`も受け付けます。

モデル数や石損条件の数は固定していません。各モデルの結果は配列の位置ではなく`dataset`で対応づけ、件数の不一致・欠損・不正な区間を検出したら描画を中止します。`elo_vs_agreement`の右パネルは`minimum_loss=2`のデータを選びます。この条件がない入力はエラーにして、別の石損条件を表示することを防ぎます。点推定値は保存済みの値を使います。同時信頼帯のために一致率を再標本化しますが、入力JSONの測定値は変更しません。
