# GGS Analyze

GGSの対局ログから、負けた組と指定した相手に引き分けた組を抽出し、Egaroucid for Console の `analyzefast` コマンドで深く読んで解析するスクリプトです。

各着手について「最善手の評価値 − 実際に打った手の評価値」を同じ探索設定で求め、1石以上損したと解析された手をすべて出力します。勝敗の予測が変わったかどうかで手を絞りません。2局の途中の評価値を足して判定する処理もありません。

棋譜の末尾から逆順に、まず最善手を探索します。最善手が実際の着手と一致した場合は、追加探索をせず石損0石とします。異なる場合だけ、同じ局面で打つ手を実際の着手に限定して探索し、最初に求めた最善手との評価値の差を計算します。二つの探索には同じ深さ・MPC確率を使います。同じ組の2局を同じConsoleプロセスで解析し、局面や対局を切り替えても置換表を消しません。

負けた組を選ぶときは2局の最終石差の合計を使い、対象の2局とも解析します。レポートと集計用の表は組単位、解析結果の明細は着手単位です。完全読みで確認した石損と、近似解析による推定を区別します。

## 必要なもの

- Python 3.9 以上 (標準ライブラリのみ使用)
- Egaroucid for Console
  - `analyzefast` コマンドと `-dpr` (手数範囲ごとの深さ・確率指定) に対応したビルドが必要です。
  - 古いビルドを指定すると、スクリプトが起動時に確認してエラーで止まります。
  - 既定では `bin/Egaroucid_for_Console_ggs_analyze.exe` を使います。リポジトリのルートで次のようにビルドしてください。

```
clang++ -O3 ./src/Egaroucid_for_Console.cpp -o ./bin/Egaroucid_for_Console_ggs_analyze.exe -mtune=native -march=native -pthread -std=c++20 -DINCLUDE_GGS -lws2_32
```

別の実行ファイルを使う場合は `--engine` で指定します。Egaroucid for Console は実行ファイルと同じ場所の `resources/` (評価関数など) を読むので、実行ファイルは `bin/` に置いてください。

## 対局ログ

GGS モードで `-ggsgamelogdir <dir>` を指定すると、1局ごとに次のようなファイルが保存されます (例: `bin/ggs/log/game/2026-09-26-22=10=28_.46.1.txt`)。

```
.46.1
black: rival_a
white: my_account
initial board: ----------OX-------O-X-----XXX----OOOO----X-O------O------------ X
transcript: c4f2d6e3g5d1g3e2c3h4c1g6f6f7h6e7d8c8f8h5c7b4b5e1a4b6a5b3g4h7f1h3b1a3a2a7b7g2g1a8b8e8h1h2h8a6g7a1b2g8
black's score: 6
```

スクリプトにはこのファイル、またはファイルが入ったディレクトリを渡します。ディレクトリはサブディレクトリまで探します (`*.txt` のみ。対局ログでないファイルは無視されます)。同じ対局が複数の場所にあっても1回だけ解析します。

## 使い方

リポジトリのルートで実行する例です。

```
# まず抽出される対局を確認する (解析はしない)
python src/tools/ggs_analyze/ggs_analyze.py bin/ggs/log/my_tournament --me my_account --vs rival_a --vs rival_b --list

# 解析する
python src/tools/ggs_analyze/ggs_analyze.py bin/ggs/log/my_tournament --me my_account --vs rival_a --vs rival_b
```

この例では、

- 負けたマッチ (相手は問わない)
- rival_a または rival_b と引き分けたマッチ

の対局をすべて解析します。解析中は1手ごとに結果と所要時間が表示されます。

終わると `bin/ggs/log/analyze/report.md` にレポートができます (出力先は `--out` で変更できます)。

解析済みの結果からレポートだけを作り直したいとき (スクリプトを更新してレポートの内容が増えたときなど) は、同じ抽出条件に `--report-only` を付けて実行します。エンジンは動かしません。

```
python src/tools/ggs_analyze/ggs_analyze.py bin/ggs/log/my_tournament --me my_account --vs rival_a --vs rival_b --report-only
```

### 途中で止める・再開する

画面には1着手ごとに、着手・評価値・解析深さ、最善手とその評価値・解析深さ、石損、解析時間を表示します。最善手が着手と同じ場合は、`最善手 着手と一致`と表示します。

起動時と1局の解析が終わるたびに、`解析完了 5/18局（2/9組）`の形式で進捗を表示します。以前の実行で完了して保存された局も数えます。組の完了数は、対象の2局とも解析が終わった時点で増えます。結果がまだ出ていない長い探索では、30秒ごとに空きマス数・経過時間・完了数を表示します。今回の9組の実行用スクリプトは、これらを画面と`reports/data_20261003_3/run.log`の両方に出力します。

完了数の後には、`ETA: 残り約1時間20分（完了見込み 10/04 00:30）`の形式で残り時間と完了日時の概算を表示します。1手の結果が出たときと30秒ごとの進捗表示でも更新します。空きマス数ごとの実測時間から未解析局面の時間を見積もり、保存済みの局面と同じ局面・同じ着手の重複は残り時間に含めません。同じ空きマス数の実測がない場合は、同じ探索設定の区間の実測を使います。今回の実測を過去の実測より優先し、探索中の局面では経過時間を引きます。必要な実測がそろうまでは`ETA: 算出待ち（解析時間を収集中）`と表示します。

解析結果は1手解析するごとに `出力先/cache/positions_*.jsonl` に書き込まれます (解析設定ごとに1ファイル)。1局が終わると、その局の結果も `出力先/cache/` に保存されます。Ctrl+C で止めたりエンジンが落ちたりしても、同じコマンドをもう一度実行すれば、解析済みの局面を飛ばして続きから再開します。`analyzefast` は棋譜の最後から逆順に解析するので、途中で止まった局は残りの序盤側だけを解析し直します。

キャッシュは「局面 + 打った手 + 解析設定」ごとなので、抽出条件を変えて実行し直しても、同じ設定で解析済みの局面は再利用されます。解析設定を変えると別物として解析し直します。キャッシュを使わずにやり直したいときは `--force` を付けます (以前の結果は消さずに、新しい結果を追記します)。

### 共通の序盤の流用

シンクロ対局の `.N.0` と `.N.1` は開始局面が同じなので、序盤の進行がしばらく同じになることがあります。そこで、同じ設定で解析済みの局面 (キャッシュにあるものを含む) と盤面・着手が同じ手は、その解析結果を流用し、まだ解析していない手だけを Egaroucid に解析させます。全ての手が解析済みなら Egaroucid は起動しません。`--jobs` で並列にしても、同じマッチの2局は同じエンジンで順番に解析するので流用が効きます。

流用した手は、実行中の表示とレポートの全着手の表 (時間の欄が「流用」) で分かります。`moves.csv` では `reused_from` 列に流用元の対局が入ります。

## 対局の抽出ルール

| オプション | 意味 |
|---|---|
| `--me NAME` | 自分のアカウント名。複数指定できます。省略するとスクリプト先頭の `DEFAULT_ME` を使います。 |
| `--vs NAME` | 負けに加えて、この相手との**引き分け**も抽出します。複数指定・カンマ区切り (`--vs rival_a,rival_b`) ができます。 |
| `--vs-only` | `--vs` で指定した相手との対局だけを抽出します (その相手への負けと引き分け)。 |
| `--draws` | 全ての相手との引き分けも抽出します。 |
| `--exclude NAME` | この相手との対局を除外します (例: 自分のテスト用アカウント)。 |
| `--unit match` / `--unit game` | 勝敗を判定する単位 (後述)。既定は `match`。 |
| `--since` / `--until` | 終局日時で絞り込みます。`2026-09-26` や `"2026-09-26 15:00"` の形式。終局日時はファイル名の日時です。 |
| `--max-games N` | 解析する対局数の上限 (古い順に N 局)。 |
| `--no-recursive` | ディレクトリのサブディレクトリを探しません。 |
| `--list` | 抽出結果を表示するだけで解析しません。 |

### マッチ単位 (`--unit match`、既定) と対局単位 (`--unit game`)

GGS の大会はシンクロ対局 (同じ開始局面を黒白入れ替えて2局打つ。ID は `.N.0` と `.N.1`) で、順位表の勝ち・負け・引き分けは **2局の合計石差** で決まります。1局ずつ見ると、ランダムな開始局面が片方の色に有利なため「マッチには勝ったが片方の局は負け」がよくあります。

- `--unit match` (既定): 2局の合計で勝敗を判定し、負け (または対象の引き分け) のマッチは **2局とも** 解析します。レポートの「組ごとの集計」で、2局をまとめた自分と相手の石損合計を確認できます。シンクロでない対局は1局で1マッチとして扱います。
- `--unit game`: 1局ごとの結果で判定します。

結果が記録されていない対局 (`black's score: -99`) と、自分同士の対局 (`--me` に両者が含まれる) は除外します。

## 解析設定

`--profile`で3種類の探索設定を選べます。省略時は`exact36`を使います。表の範囲は空きマス数です。

| 探索 | `original`：最初の設定 | `exact32`：直前の設定 | `exact36`：既定 |
|---|---|---|---|
| 完全読み（100%） | 1～30 | 1～32 | 1～36 |
| 終局まで、MPC 99% | 31～34 | 33～34 | 37～39 |
| 終局まで、MPC 98% | 35～37 | 35～36 | 40～43 |
| 終局まで、MPC 93% | 38～40 | 37～38 | 44～47 |
| 終局まで、MPC 88% | 41～43 | 39～40 | 48～51 |
| 終局まで、MPC 74% | なし | 41～46 | 52～55 |
| 中盤探索 | 44～60：深さ35・MPC 74% | 47～60：深さ35・MPC 88% | 56～60：深さ39・MPC 88% |

今回の9組の実行用スクリプトでも、同じようにプロファイルを指定できます。

```powershell
# 既定の exact36
python -X utf8 -B reports/20261003_3_ggs_loss_analysis.py
# 最初の設定
python -X utf8 -B reports/20261003_3_ggs_loss_analysis.py --profile original
# 32マス空きまで完全読みの設定
python -X utf8 -B reports/20261003_3_ggs_loss_analysis.py --profile exact32
```

一般の対局ログを解析する場合も、`ggs_analyze.py`に`--profile`を付けます。選んだ名前を画面・ログ・レポートに表示します。キャッシュは実際の探索設定ごとに分かれ、`original`と`exact32`では以前の同じ設定の結果を再利用できます。

個別の探索オプションを付けると、選んだプロファイルの該当項目を上書きします。次の既定値欄は`exact36`の値です。

| オプション | 既定 | 意味 |
|---|---|---|
| `--profile` | exact36 | original / exact32 / exact36 から選ぶ |
| `--mid-depth` | 39 | 中盤探索の深さ |
| `--mid-prob` | 88 | 中盤探索の MPC 確率 |
| `--end-empties` | 55 | この空きマス数から終盤読み切りにする |
| `--exact-empties` | 36 | この空きマス数から完全読みにする |
| `--end-probs` | 74,88,93,98,99 | 終盤読み切りの区間を空きマス数の多い側から順に使う MPC 確率 |
| `--end-sizes` | 4,4,4,4,3 | 各確率に割り当てる空きマス数の幅。個数は確率の個数と同じ、合計は終盤読み切り開始と完全読み開始の空きマス数の差にする |
| `--book` | なし | book を使う。既定では book を使わず全局面を上の設定で探索します |
| `--threads` | 論理コア数 / `--jobs` | 1エンジンあたりのスレッド数 |
| `--jobs` | 1 | 同時に動かすエンジンの数。スレッド数を増やしても効率が落ちる場合は、`--jobs 2` などでマッチ単位で並列にすると速くなることがあります。メモリはエンジンの数だけ必要です |
| `--hash` | 29 | 置換表の大きさ (`-hash`)。29 だと1エンジンあたり約16GB (2^29 エントリ × 32 バイト) のメモリを使います。メモリが足りない場合は小さくしてください |
| `--engine-arg` | なし | エンジンに追加で渡す引数 (`--engine-arg=-seed --engine-arg=1` のように1つずつ指定) |
| `--mistake-threshold` | 4 | 実行中の表示で「悪手」と表示する石損の基準。レポートはこの値に関係なく1石以上の石損をすべて掲載する |
| `--report-only` | なし | エンジンを動かさず、キャッシュ (解析済みの対局と1手ごとの結果) からレポートと CSV だけを作り直します。解析が終わっていない対局は「まだ解析していない対局」として一覧に出します |
| `--client-log` | 対局ログの場所から探す | 対局時の読みを取る GGS クライアントのログ (`*_ggs.log`) またはそのディレクトリ (後述) |

使われる確率は `74, 88, 93, 98, 99, 99.9, 100` のどれかです。contest book は使いません (`-nocontestbook`)。

設定は Egaroucid for Console の `-dpr <開始手数> <終了手数> <深さ> <確率>` に変換して渡しています (手数 = 61 − 空きマス数、終盤読み切りは深さ 60 で指定)。実際に使ったコマンドは実行時に表示されます。手で同じことをする場合は次のようになります。

終盤の範囲や確率を個別に変更し、`--end-sizes`を指定しなかった場合は、その区間を確率の数で均等に分割します。隣接する同じ確率の区間はまとめます。名前付きプロファイルの区間幅は上の表どおりに固定されています。

```
bin/Egaroucid_for_Console_ggs_analyze.exe -quiet -nobook -nocontestbook -t 28 -hash 29 -dpr 1 5 39 88 -dpr 6 9 60 74 -dpr 10 13 60 88 -dpr 14 17 60 93 -dpr 18 21 60 98 -dpr 22 24 60 99 -dpr 25 60 60 100
setboard <初期盤面>
play <棋譜>
analyzefast
```

### 所要時間の目安

深く読むので時間がかかります。旧`analyze`コマンドと以前の探索設定（完全読み30マス空き以下、終盤読み切り43マス空き以下）を使い、28 スレッド 1 エンジンで大会の1局 (50手) を解析した例では、

| 区間 | 局面数 | 合計時間 | 1局面あたり |
|---|---:|---:|---|
| 完全読み (30〜1空き) | 30 | 約17秒 | 30空きで約9秒 |
| 終盤読み切り (43〜31空き) | 13 | 約16分 | 4秒〜4分 (空きが多いほど長い) |
| 中盤探索 深さ35 (44空き〜) | - | - | 44空きで約22秒 |

でした。時間の大半は終盤読み切りの区間 (特に 43〜37 空き) です。局面によって大きく変わります。

まず `--mid-depth 21 --end-empties 30 --exact-empties 24` のような軽い設定で全体を見て、気になる対局だけ既定の設定で解析し直すのもおすすめです (設定ごとにキャッシュされます)。

## 出力

出力先 (既定: `bin/ggs/log/analyze/`) に次のファイルができます。レポートと CSV は実行のたびに、その回に抽出した対局の内容で上書きされます。

| ファイル | 内容 |
|---|---|
| `report.md` | 解析レポート (Markdown) |
| `matches.csv` | 1組1行の集計。片方だけ解析済みの場合は石損の集計欄を空欄にする |
| `moves.csv` | 1手1行の解析結果 (盤面文字列、打つ前の石数、対局時の読み・評価・思考時間つき) |
| `cache/` | 1局ごとの解析結果 (再開・再利用用の JSON) |

### report.md の内容

- 要約、用語の定義、解析条件。
- 組ごとの解析着手数、石損した手数、石損合計。
- 空きマス数ごとの解析着手数、石損した手数、石損合計。
- 組ごとの、自分と相手が石損した手の一覧。着手、最善手、二つの評価値、石損、二つの解析深さ、対局時の探索深さ・時間を示す。
- 自分が石損した全着手の盤面図、初期局面、棋譜、全着手の解析結果。

「最後に勝敗が変わった手」を一つ選ぶ処理は廃止しました。1局の勝敗と、組の途中の予想石差は、石損の判定に使いません。`moves.csv`の旧列`result_worsened`と`eval_me_before`、局単位の集計ファイル`games.csv`も廃止しました。既存の解析用キャッシュは再利用できます。

### 石損の判定

評価値は、その着手を打つ側から見た最終石差です。同じ局面の同じ探索設定で最善手と実際の着手を比べます。

```text
石損 = max(0, 最善手の評価値 − 実際に打った手の評価値)
```

例えば、最善手が+8石で実際の着手が+6石なら2石損、最善手が−10石で実際の着手が−12石でも2石損です。両方が勝ち、または両方が負けの予測でも抽出します。1石の差も掲載します。

比較した二つの評価値が、ともに終局までMPC確率100%で求められた場合だけ「完全読みで確認」と記載します。それ以外は「近似解析による推定」と記載します。

盤面文字列はそのままEgaroucid for Consoleの`setboard`に使えます。

### 対局時の読みの取得

対局時の読み・評価・思考時間は、GGS クライアントのログ (`-ggslogdir` / `-ggslogfile` で出力される `*_ggs.log`) の `search ready` などの行から、対局 ID・盤面・着手で対応付けて取ります。ログは対局ログのディレクトリ (再帰的) とその親ディレクトリから探し、対局の終局時刻にそのセッション (ファイル名の開始時刻〜最終更新時刻) が動いていたものを使います。`--client-log`を指定した場合は、そのファイルまたはディレクトリだけを検索します。指定しない場合は棋譜の場所から自動で探します。対応付けられなかった手は「-」(集計では「不明」) になります。探索の深さが記録されていない古いログ (2026年6月頃まで) からは取れません。

### 注意

- 中盤探索と MPC つき終盤読み切りの評価値には誤差があります。特に中盤の 1〜2 石の損失は誤差の可能性があります。完全読みの区間 (既定では 36 マス空き以下) の評価値と損失は正確です。
- 時間切れ・投了などで終局前に終わった対局は棋譜の最後まで解析し、盤上の評価より結果が悪い場合はレポートに注意を表示します。
- 相手の手の損失も同じように計算しているので、相手が間違えたのに自分がそれを活かせなかった場所も分かります。
