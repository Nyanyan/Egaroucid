# 平均石損に合わせる隣接レート帯のブレンド

対象レート帯のFT済みPolicy Networkと、一段下のレート帯のFT済みPolicy Networkを幾何平均でブレンドします。検証データで、人間の実際の着手の平均石損に近づくαを選び、そのαを固定してテストデータを評価します。

## 方策と評価条件

合法手 `a` の確率は、`P(a) ∝ P_対象帯(a)^(1−α) × P_下位帯(a)^α` です。α=0は対象帯、α=1は下位帯です。ブレンド後に最大確率の合法手を選び、同点ではpolicy indexが最小の手を選びます。対象帯・下位帯という呼び方は学習データのレート帯を示し、実測の棋力順を保証するものではありません。

確率の幾何平均は、softmax直前のlogitsを加重平均することで計算します。これは合法手上の正規化確率の幾何平均と同じTop-1を与えます。Conv8+BNの60出力は、既存モデルと同じ座標で64マスへ対応付けます。

石損は既存の人間・FTモデルの測定と同じ `analyze` で求めます。既定ではEgaroucid lv.10、bookなし、各エンジン1スレッドです。`setboard → play 選択手 → analyze` で選択手と最良の別の手を評価し、`max(選択手の評価, 別の手の評価) − 選択手の評価` を石損とします。別の手がなければ石損は0です。探索キャッシュは保持し、clearcacheは行いません。

検証では、αを0〜1で変えたときにTop-1になり得る手と人間の実際の手だけを解析します。各手のlogitsはαの一次式なので、他の全手以上になるαの区間を調べると、細かいα走査を含めて必要な手を漏れなく列挙できます。α間で同じ局面・同じ手の石損を共有し、合法手が1つなら探索なしで石損0とします。テストでは検証で採用したαの手だけを解析します。

初版の全合法手hint 100・毎局面clearcacheの処理は、不要な探索とキャッシュ消去で時間がかかるため停止し、この方式へ変更しました。初版の `scores.npy` は現在の石損計算には使いません。

採用済みモデルは、既存キャンペーンで検証成績から選ばれた `selected_model.h5` を使います。モデル・入力データ・エンジン資源のハッシュを記録し、再開時も照合します。検証・テストは水増し前の全局面を使い、重複局面、石損0の着手、合法手が1つの局面も平均の分母に含めます。パスは含めません。検証とテストの棋譜IDが重複していないことも確認します。

## 実行

このフォルダで次のコマンドを実行します。PythonはTensorFlow、NumPyなど、既存の学習環境のライブラリを利用します。`-Python`でPython実行ファイルを指定できます。

```powershell
powershell -NoExit -ExecutionPolicy Bypass -File .\run_fit_blend.ps1 -Band 1400-1600 -Workers 24
```

初回の対象は [1400,1600) と [1200,1400) のモデルです。別の帯は `-Band 1600-1800` などで指定します。全帯は `-AllBands` を付けます。最下位の800未満には一段下のモデルがないため、全帯実行の対象は [800,1000) から2200以上までの8帯です。

既定のキャンペーンはリポジトリ内の `experiment_bat/20261010_quest_rating_bands` です。別のキャンペーンを使う場合はPythonスクリプトに `--campaign` を渡します。同じ構成の採用モデル情報と、検証・テストの検証済みキャッシュが必要です。

```powershell
python .\fit_blend_to_loss.py --campaign <campaign-directory> --band 1400-1600 --workers 24
```

αは0〜1を0.001刻みで全域走査し、平均石損の絶対誤差が最小の点の前後0.001を201点で再評価します。既定の細かい刻みは0.00001です。同じ誤差なら小さいαを採用します。Top-1の平均石損は段階的に変わり、単調とは限りません。この方法は有限の候補から最も近い点を選ぶもので、連続区間全体の厳密な最適解を保証するものではありません。目標が走査で観測した範囲内かどうかも保存します。

小規模な動作確認には `-MaxPositions 16 -AlphaIntervals 20` を指定します。この場合は各分割の先頭16局面を使い、結果を別フォルダへ保存し、部分評価であることを明記します。

## 進捗と保存先

可視コンソールには、推論・エンジン評価・α走査の進捗、経過時間、推定残り時間を表示します。ログは `output/run_<band>_<timestamp>.log` に保存します。Ctrl+Cまたはウィンドウを閉じると計算と子エンジンが停止します。同じコマンドを再実行すると、保存済みの推論とエンジン評価を確認して再利用します。同じ結果フォルダの二重起動はロックで防ぎます。

結果は `output/1400-1600_l10/` などに保存します。

- `selected_alpha.json`: 人間の検証平均石損、採用α、ブレンドの検証平均石損、絶対誤差。
- `validation_alpha_curve.csv`: 走査したαと検証平均石損。
- `result.json`: モデル・データ・エンジン条件、採用α、テスト平均石損。
- `test_result.csv`: 採用αのテスト評価。
- `val/` と `test/`: ハッシュ付き推論情報、局面・選択手ごとのanalyze評価キャッシュ、進捗。人間の局面別石損は `val/human_losses.npy` に保存します。
- `test/blend_moves.npy` と `test/blend_losses.npy`: 採用αのテスト着手と局面別石損。

`result.json` の `status` が `complete` になれば、検証でのα選択とテスト評価が完了しています。

保存結果の再検算は次のコマンドで実行できます。元データとモデルのハッシュ、幾何平均から選んだ合法手、局面・着手とanalyzeキャッシュの対応、石損の合計、検証・テストの棋譜IDを確認します。平均は整数合計を元の局面数で割って再計算し、`verification.json` に保存します。

```powershell
python .\verify_result.py --output .\output\1400-1600_l10
```

## [1000,1200) モデルとの2組の検証α探索

`fit_validation_model_pairs.py` は、[1000,1200) と [1200,1400)、および [1000,1200) と [1400,1600) のFTモデルを比較します。どちらも同じ [1400,1600) の検証データ117,606局面を使い、人間の平均石損を目標にαを選びます。α=0は [1200,1400) または [1400,1600)、α=1は [1000,1200) です。

```powershell
powershell -NoExit -ExecutionPolicy Bypass -File .\run_validation_model_pairs.ps1 -Workers 24
```

2組で必要な着手をまとめて解析します。以前の検証・学習評価のキャッシュから、同じエンジン条件・同じ局面・同じ手の完了済み評価を再利用します。停止した学習データ評価の計算は再開しません。各エンジンは1探索スレッドで動き、24件を並列に解析します。

α走査では、0〜1の全区間でTop-1になり得る手を事前に列挙し、その候補だけで計算します。0.001刻みの全域走査後、最良点付近を201点ずつ3段階で再評価し、既定の最も細かい刻みを0.000000001にします。候補を絞ってもTop-1の結果が全合法手からの選択と一致することを検証します。有限の候補からの選択であり、連続区間全体の厳密な最適性を主張するものではありません。

結果は `output/validation_1400-1600_pairs_1000_l10/results.csv` と `results.json` に保存します。組ごとのフォルダにはαの曲線、採用α、両端モデルの平均石損、選択手と局面別石損を保存します。このスクリプトは検証データでのα探索だけを行います。

2026年10月14日の全検証117,606局面での結果は次のとおりです。α=1側の [1000,1200) FT単独の平均石損は4.525100760で、人間の目標3.660399980を上回ります。

| α=0側のFTモデル | α=1側のFTモデル | 採用α | ブレンド平均石損 | 人間との差の絶対値 |
| --- | --- | ---: | ---: | ---: |
| [1200,1400) | [1000,1200) | 0.411341551 | 3.660408483 | 0.000008503 |
| [1400,1600) | [1000,1200) | 0.7643223950000001 | 3.659923813 | 0.000476166 |

2組とも、保存着手が全合法手から計算した幾何平均のTop-1と一致すること、局面・着手に対応するanalyze評価から石損の合計を再現できること、採用αが保存した走査曲線で最小の誤差を与えることを再確認しました。人間の目標値は前回の検証結果と一致しています。検算記録は `verification.json` に保存しています。

採用αでの検証着手一致率も、保存済みの117,606着手から集計しました。テストと同じく、盤面を保つ回転・鏡映で同等になる手を正解に含めるTop-1です。

## 採用した2組のテスト平均石損と着手一致率

`evaluate_model_pairs_test.py` は上記の検証結果からαを読み込み、[1400,1600) の水増し前テスト全125,812局面に適用します。テストでαを調整せず、検証時のモデルと係数を固定して平均石損と着手一致率を求めます。

```powershell
powershell -NoExit -ExecutionPolicy Bypass -File .\run_model_pairs_test.ps1 -Workers 24
```

着手一致率はTop-1で、盤面の自石・相手石を保つ回転・鏡映で人間の実際の手と同等になる手も正解とします。テストの正解集合を元の盤面から再生成し、既存キャッシュの正解集合と照合します。平均石損はEgaroucid lv.10の `analyze`・探索キャッシュ保持方式で、同じ局面・選択手の完了済み評価を再利用します。各エンジンは1探索スレッド、24件並列です。

結果は `output/test_1400-1600_pairs_1000_l10/results.csv` と `results.json` に保存します。`predictions.npy` と `losses.npy` は、元のテスト局面順に [1200,1400) → [1000,1200)、[1400,1600) → [1000,1200) の2列を保存します。完全一致だけの件数は診断用に記録し、主指標は対称性を考慮した一致率です。`-MaxPositions 16 -Workers 4` は別フォルダでの小規模確認に使います。

2026年10月14日のテスト全125,812局面での結果は次のとおりです。

| α=0側のFTモデル | α=1側のFTモデル | 固定α | テスト平均石損 | 対称性を考慮したTop-1一致率 | 一致件数 |
| --- | --- | ---: | ---: | ---: | ---: |
| [1200,1400) | [1000,1200) | 0.411341551 | 3.628326392 | 55.613137% | 69,968 / 125,812 |
| [1400,1600) | [1000,1200) | 0.7643223950000001 | 3.644231075 | 55.032906% | 69,238 / 125,812 |

検証時のαとの一致、保存した着手と幾何平均Top-1の一致、局面・着手とanalyze評価の対応、石損合計と一致件数の独立した再集計を確認済みです。検証・テスト間の棋譜IDの重複はありません。検算記録はテスト出力の `verification.json` に保存しています。

## 対称的な別の手を正解として数えることの独立監査

`audit_symmetry_accuracy.py` は、既存の対称変換マップを使わず、8×8の自石・相手石・人間着手の配列を回転・反転して正解集合を再構成します。自石と相手石の配置がそれぞれ元の盤面と一致する変換だけを採用します。その変換で人間の手が移る別のマスも正解になります。

```powershell
python .\audit_symmetry_accuracy.py
```

検証117,606局面とテスト125,812局面の全243,418局面で、既存の正解集合と独立した配列変換の結果が一致しました。対称的な別の手がある局面は、検証2,500局面、テスト2,655局面です。

| データ | α=0側のFTモデル | 完全一致のみ | 対称性を考慮した一致率 | 対称的な別の手として追加された一致件数 |
| --- | --- | ---: | ---: | ---: |
| 検証 | [1200,1400) | 53.764264% | 55.511624% | 2,055 |
| 検証 | [1400,1600) | 53.251535% | 55.001446% | 2,058 |
| テスト | [1200,1400) | 53.874829% | 55.613137% | 2,187 |
| テスト | [1400,1600) | 53.293803% | 55.032906% | 2,188 |

例えばテスト局面index 22では、人間の手f4とNNの手d6を同等な手として一致に数えています。この盤面は7石の局面で、正解集合はf4とd6です。監査結果と実例の盤面ビットボードは `output/symmetry_accuracy_audit.json` に保存しています。
