# 評価精度を測る局面集

50〜41マス空きの局面62件に、複数の候補手の参照値を付けた。参照値は手番側の予想最終石差であり、候補内最大値−選択手の値を石損として採点する。候補以外の最善手を含む保証はない。

## 形式

`eval_stick.jsonl` は1行1局面。`board` はa1、b1、…、h8の64文字で、`X`は黒、`O`は白、`-`は空き。`turn`は手番、`empties`は空きマス数、`source`は出典と対称変換、`game`と`pair`は主出典の対局と組、`selection_order`は固定処理順である。

`candidates` は手ごとの `move`、`value`、`settings`、`cache_key`、候補へ加えた `reason` を持つ。`settings`には探索深さ、MPC、28スレッド、置換表設定28、実行ファイルと資源のSHA-256を記録した。`best_move`は候補内最大値の手を座標順で1手選んだもの、`best_moves`は同値をすべて含む。`reference_noise_flag`は1段高いMPCでの確認が `stable`（変化なし）、`changed`（最善手集合または候補間関係が変化）、`unchecked`（未確認）のいずれかである。

## 作り方

GGSの分岐と負けの分類①②の局面、10月9日・16日・17日・17日大会・23日の保存棋譜を再生し、回転・反転の重複を除いた。初期200局面を各空きマス数20件、同じ元対局の同じ2空きマス幅で1件までとして選んだ。抽出の種は202610263。本測定では抽出順位とは別に、各空きマス数の中を種202610264で無作為に並べ替えて交互に処理する。費用測定用の5局面は別に固定し、本測定の無作為な対象にも選ばれた場合だけ比較へ含める。費用測定後の対象数は62件。候補は記録手、NNUE版の深さ24・MPC 88%の上位4手、同条件のパターン版の最善手、比較で実際に選ばれた追加手である。

参照はパターン版の根の1手限定探索で終局まで読む。50〜48マス空き88%、47〜44マス空き93%、43〜41マス空き98%。28スレッド、置換表設定28、同一局面内で置換表を共有し、局面を変えると消した。参照の累積実時間は16.375時間。詳しい費用・未解決・生出力・実行ファイルは `reports/20261026_3_eval_stick.md` と `reports/data_20261026_3/` にある。

## 採点

```powershell
python src/tools/eval_stick/score_eval_stick.py --engine <実行ファイル> --out <出力先> -- -thread 8 -hash 28 -movetime 3000
```

指定したエンジンへ `-solve` で局面を渡す。各局面の前に置換表を消す経路である。`results.jsonl`に選択手・到達深さ・実探索時間・石損・最善手一致を保存し、未採点の手を `summary.json` に列挙する。候補外を石損0として扱わない。定石は使わない。

抽出は `python src/tools/eval_stick/build_eval_stick.py pool`、保存済み参照からの再出力は同じスクリプトの `publish`。今回の工程全体は `reports/20261026_3_run.py`。完了した値は設定と実行ファイルのSHA-256が一致する場合だけ再利用する。

## 制約

参照はMPCを使う読み切りであり、完全読みの正解ではない。候補の全合法手を最終強度で読んだものでもない。同じ最大値の手はすべて最善手一致として数える。分岐と負けを優先した選択なので、実戦全着手の損の頻度とは異なる。同じ対局から複数の局面があるため、不確かさは対局をまとめた計算でも確認する。参照値の絶対値が16石以上の大差局面も同じ強度で探索する。
