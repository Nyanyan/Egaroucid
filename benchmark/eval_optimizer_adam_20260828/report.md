# Egaroucid評価関数のAdam再学習調査

調査日: 2026-08-28～2026-08-29  
対象フェーズ: 11、12、21、30、41  
固定seed: `20260828`

## 結論

今回の結果は、「Adamが全重みを一様に小さい尺度にしたまま収束している」という説明を支持しなかった。

- **実測で確認:** 教師値を `z`、連続値重みによる評価値を `e` とすると、`e = a z + b` の傾き `a` は0.765～0.922だった。一方、逆向きの `z = c e + d` の傾き `c` は、学習集合で1.000000～1.000346、固定検証集合で0.998846～0.999980だった。
- **実測で確認:** 学習集合では `a` と回帰のR²がほぼ一致し、`Cov(e, z-e)` もほぼ0になった。これは、平均値（切片）を合わせた上で全評価値を同率で拡大・縮小する方向には、MSEを下げる余地がほぼ残っていない状態である。
- **実測からの推定:** 現在使用中の重みと今回の再学習重みは、同じ学習集合上でMSEも傾きもほぼ同じだった。MSE/MAE集計用配列の競合、初回勾配の二重加算、検証用レコードの非固定は実在したが、今回の5フェーズでは、教師値 `z` に対する順方向回帰傾き `a<1` の主因だったことを示す結果は得られなかった。厳密な寄与量には旧実装との同一seed A/Bが必要である。
- **実測で確認:** 連続値重みから最近傍整数重みへ変換したときの順方向傾きの変化は+0.00049～+0.00098だった。少なくとも教師値 `z` に対する傾きについて、整数化は主因ではない。
- **実測で確認:** フェーズ21と30は時間上限より前に早期終了した。ただし停止直前のMSE改善は極小で、逆方向傾きもすでにほぼ1だった。最良重みを復元しないことも、教師値 `z` に対する今回の順方向傾き差の根本原因ではない。

したがって、現象を正確に言い直すと次のようになる。

> Egaroucidの評価値 `e` を教師値 `z` で単回帰した直線は、傾きが0.765～0.922になる。しかし、逆向きの回帰傾きはほぼ1であるため、「Adamが全重みを一様に小さくした」とは説明できない。実測結果は、MSEによる最小二乗射影で予測できない残差が残った場合の形と整合する。

平たく言えば、平均値を補正した後、現在の評価値全体を一律に拡大する必要はほぼない。それでも評価値に含まれない残差があるため、「教師値を横軸にした傾き」だけは1未満になり得る。今回実測したのはこの形であり、Adamがすべての重みを同じ割合で小さくした形ではなかった。個々の特徴方向まで十分に収束したかは、別途確認が必要である。

これは `e` と `z` の比較から言える範囲である。今回は正確なminimax値 `v` を再計算していないため、既報の `e` 対 `v` の傾きが1未満になる原因全体を、この実験だけで確定または否定するものではない。

**未確認／追加実験が必要:** 残差が生じる内訳が、教師値の揺らぎ、同一特徴表現への異なる教師値、既存特徴で表せない相互作用、またはAdamの局所的な未収束のどれであるかは、今回の実験だけでは分離していない。

## なぜ順方向傾きだけではAdamの尺度不足を判定できないか

平均を差し引いた値を考える。評価値を作るのに使える信号を `s`、その信号と無相関な残差を `n` とし、教師値が `z=s+n`、評価値が `e=s` だったとする。これは、`s` を最小二乗射影で得られる部分、`n` をそれと直交する残差と置いた例であり、`Cov(s,n)=0` が成り立つ。この評価値は予測可能な部分を完全に再現している。それでも、`e` を `z` で回帰した傾きは次のように1未満になる。

```text
slope(e on z) = Var(s) / (Var(s) + Var(n))
```

MSEの尺度方向が収束したかを調べるには、逆向きの傾きと残差の相関を見る必要がある。

```text
c = slope(z on e)
Cov(e, z-e)
```

`c=1` かつ `Cov(e,z-e)=0` なら、平均値（切片）を合わせた上で全評価値を同率で拡大・縮小してもMSEは改善しない。このとき、順方向傾き `a` はR²と一致する。今回の5フェーズはほぼこの状態だった。

## 実施した修正

### 1. MSE/MAE集計用配列の初期化競合

**ソースで確認:** 旧実装では、複数blockが `atomicAdd` している集計用配列を、同じkernel内の1 threadが0で上書きしていた。block間の実行順序は保証されないため、MSEとMAEが欠落する競合だった。

修正後は、各kernelを起動する前にhost側から `cudaMemset` し、kernel内の初期化を削除した。4,099件を複数blockで処理する自己テストを20回繰り返し、学習、検証、整数丸めの集計値が毎回 `MSE=1`、`MAE=1` になることを確認した。

この競合は勾配配列を直接壊すものではない。ただし、検証MSEを通じて学習率低下と早期終了へ、丸めMSEを通じて整数丸め方の探索結果へ影響し得る。

### 2. 最初のAdam更新だけ勾配が二重だった問題

**ソースで確認:** 旧実装は、学習開始前のMSE表示に勾配も蓄積するkernelを使い、最初の反復で同じ残差をもう一度加えていた。最初のAdam更新だけ、勾配が2回分入っていた。

開始前の測定を勾配へ書き込まない集計kernelへ変更した。以後、各Adam更新には残差が1回だけ入る。

### 3. 検証用レコードの固定

検証分割専用に、処理手順をソース内で固定したSplitMix64とFisher–Yatesシャッフルを実装し、seed `20260828` で初期化した。C++標準ライブラリの `std::shuffle` には依存しない。整数丸め用の乱数生成器とも分離した。テストデータは読み込みも変更もしていない。

検証集合の指紋は、検証レコードの一部ではなく全件から計算するようにした。1,529件の同じ入力を別プロセスで2回読み直し、整数丸め用seedも1と999に変えた確認では、検証76件の指紋が両方とも `0x3bf7e874712721ba` になった。

フェーズ11は従来仕様を維持し、全件を学習と検証の両方に使った。したがって、フェーズ11の検証値は独立検証ではない。

この分割単位は、連結後の `Adj_Data` 1レコードである。盤面や元棋譜をまとめた分割ではないため、重複盤面や同一棋譜由来のレコードが学習側と検証側をまたぐ可能性がある。今回依頼された「検証用レコードを同じseedで固定する」処理だけを行い、既存の別テストデータには手を加えていない。

### 4. 学習段階ごとの記録

次の段階で、MSE、MAE、平均誤差 `mean(e-z)`、両方向の回帰傾き、R²、`Cov(e,z-e)` を保存した。

- 現在使用中の参照重み
- 0初期値
- Adam学習中25反復ごと
- Adam終了時の連続値重み
- 最近傍整数化直後
- 60秒の整数丸め方の探索後

連続値重みも別ファイルへ保存した。これにより、Adamと整数化の影響を分離できるようになった。

順方向傾きを1にするだけなら、評価値を `1/a` 倍すればよい。しかし、フェーズ11は学習集合、他のフェーズは固定検証集合でbiasも補正して計算すると、教師値に対するMSEは次のように悪化する。

これは同じ教師データ上の計算であり、正確なminimax値に対して同じ悪化率になるとは限らない。ただし、「順方向傾きが0.8だから全重みを1.25倍する」という補正は、教師値へのMSEを明確に悪化させる。

MSEを最小にする事後の倍率は逆方向傾き `c` であり、今回の `c` はほぼ1だった。したがって、通常の線形尺度補正を追加してもほとんど変わらない。

## 次に何をすれば原因をさらに分離できるか

### Adamにまだ改善余地があるかを確認する

今回確認したのは「全重みを一律に拡大する方向が収束している」ことまでである。他の重み方向が完全に収束したことまでは証明していない。

次の診断を追加する。

1. Adam終了時に、612,425個の全重みに対する勾配ノルムを保存する。
2. Adamと別solverで、出現しない係数を固定し、同じレコード・同じ開始重み・同じ更新対象を使う。
3. L-BFGSまたは共役勾配法を、Adamと同じ時間だけ、または勾配ノルムが所定の収束許容値に達するまで実行する。
4. 第一判定指標を学習MSEと勾配ノルム、汎化確認を固定検証MSEとする。R²と傾きは副指標として記録する。

Egaroucidの現行モデルは重みに対して線形で、MSEは凸二次関数である。別の最適化手法が同条件で学習MSEをさらに下げ、固定検証MSEも改善するなら、Adamまたは停止条件に改善余地がある。学習MSEを下げられず、勾配ノルムも十分小さいなら、少なくとも現行MSEに対するAdam未収束説は弱くなる。この比較は実行時速度を変えない。

### 残差がどこから来るかを確認する

次を学習集合と固定検証集合で集計する。

1. 教師石差帯ごとの `mean(e-z)` と傾き。
2. 65個の特徴indexが完全に同じレコードをまとめ、異なる教師値が付く割合と条件付き分散を測る。
3. データIDごとの残差と、同じ局面の重複回数による重み付け効果を測る。

これにより、教師値の揺らぎ、同一特徴表現への矛盾、特定データ源の偏りを分けられる。今回の結果だけから「モデル表現力不足」とは結論しない。

## 0方向への寄りを直接減らす学習案

実行時特徴を追加せず、学習だけを変える候補は次の順で試す。

1. 現行MSEを基準として残す。
2. 教師石差帯ごとの平均残差を罰するlossを少量加える。

```text
L = MSE + lambda * sum_b weight_b * mean(e-z | z is in score band b)^2
```

3. 代案として、教師石差帯ごとの重み付きMSEを試す。絶対値の大きい教師値を少し重くするが、重みは固定検証集合で調整する。
4. unweighted MSE、MAE、順方向傾き、逆方向傾き、兄弟順位を同時に比較し、独立テストデータで採否を決める。

このlossは、教師石差の大きい帯で平均的に0へ寄る現象を直接対象にする。推論コードと特徴数は変わらないため、実行時速度も変わらない。一方、MSEとのトレードオフは必ず測る必要がある。

最初に行うべき実装は、Adamの学習率を勘で変えることではない。同じ開始重み・同じ学習時間で、別の最適化手法が学習MSEをさらに下げられるかを確認する。下げられるならAdamまたは停止条件を直す。下げられない場合も、それだけでAdamの収束を断定せず、正規化した勾配が十分小さいこと、または別の最適化手法を収束許容値まで動かしてもMSEが下がらないことを確認する。その確認後に、石差帯ごとの平均誤差を抑える追加損失を試す。この順なら、原因と対策を混同しない。
