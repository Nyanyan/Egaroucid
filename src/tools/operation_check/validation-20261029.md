# Windows GUI実操作の検証記録（2026年10月29日、Issue #652）

リリース判定は未合格です。実GUI操作の必須30項目のうち、修正段階の異なるビルドを通じて22項目を確認しました。
ドラッグ、ファイル読込画面の取消、オセロクエストの詳細取得・取込、Egaroucid Windows配布インストーラーの確認が残っています。

## 環境と確認方法

Windows 11、Microsoft IME、GUI 7.8.3 Windows x64 SIMD (MSVC) Portable、日本語、表示倍率1.0で確認しました。
GUIは公式のVisual Studio用スクリプトでビルドしています。
各実行では、実行ファイルとリソースを確認用フォルダにコピーし、専用の設定・Book・対局データを使いました。
元の個人設定とBookの9ファイルは、確認後もSHA-256が一致しました。

クリック、キー入力、IME変換、クリップボード操作は、`@oai/sky`から実際のWindows入力を送って行いました。
アプリの読み取り専用の状態記録に加え、保存されたJSON、CSV、Book、PNGとOSのクリップボードを比較しています。
内部関数を呼ぶ基礎確認は、実GUI操作とは別に集計しました。

### 短時間ドラッグの切り分け

読み取り専用のマウス入力記録を追加し、`desktop_mouse/20261029-201543-835700/desktop/desktop-mouse.tsv`に保存しました。
定石のドラッグでは、Windowsの押下メッセージがクライアント座標(447,288)、移動メッセージが(447,208)で、同じフレーム3157に届いていました。
このフレームのSiv3D側は左ボタンのdown・pressedがともに1で、カーソルは既に終点のシーン座標(298,138)でした。
約16ミリ秒後、フレーム3158にはボタンを離したメッセージが届いています。

定石一覧は`MouseL.down()`時の現在の`Cursor::Pos()`を開始位置として保存します。
そのため、この短い入力では終点を開始位置として記録し、ドラッグ判定に必要な移動距離を検出できませんでした。
Skyのdragには所要時間の指定がなく、同じ操作ツールで遅いドラッグに変更することはできません。
今回、アプリのドラッグ処理自体は変更していません。通常速度の手操作での確認と、短時間入力をどう扱うかの対応が残っています。
