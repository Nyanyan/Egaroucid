# GGS Analyze

GGS の対局ログから「負けた対局」と「特定の相手に負けた・引き分けた対局」を抽出し、Egaroucid for Console の `analyze` コマンドで深く読んで解析するスクリプトです。

各局面について「実際に打った手の評価値」と「それ以外で最善の手の評価値」を同じ探索設定で求め、どの手で何石損したか、どの手で勝敗が決まったか (敗着候補) をレポートにまとめます。

## 必要なもの

- Python 3.9 以上 (標準ライブラリのみ使用)
- Egaroucid for Console
  - `analyze` コマンドが `-dpr` (手数範囲ごとの深さ・確率指定) に対応したビルドが必要です (コミット `856002973` 以降)。
  - 古いビルドを指定すると、スクリプトが起動時に確認してエラーで止まります。
  - 既定では `bin/Egaroucid_for_Console_clang.exe` を使います。リポジトリのルートで次のようにビルドしてください。

```
clang++ -O3 ./src/Egaroucid_for_Console.cpp -o ./bin/Egaroucid_for_Console_clang.exe -mtune=native -march=native -pthread -std=c++20 -DINCLUDE_GGS -lws2_32
```

別の実行ファイルを使う場合は `--engine` で指定します。Egaroucid for Console は実行ファイルと同じ場所の `resources/` (評価関数など) を読むので、実行ファイルは `bin/` に置いてください。

## 対局ログ

GGS モードで `-ggsgamelogdir <dir>` を指定すると、1局ごとに次のようなファイルが保存されます (例: `bin/ggs/log/game/2026-09-26-22=10=28_.46.1.txt`)。

```
.46.1
black: rival_a
white: my_account
initial board: ----------OX-------O-X-----XXX----OOOO----X-O------O------------ X
transcript: c4f2d6e3g5d1g3e2c3h4c1g6f6f7h6e7d8c8f8h5c7b4b5e1a4b6a5b3g4h7f1h3b1a3a2a7b7g2g1a8b8e8h1h2h8a6g7a1b2g8
black's score: 6
```

スクリプトにはこのファイル、またはファイルが入ったディレクトリを渡します。ディレクトリはサブディレクトリまで探します (`*.txt` のみ。対局ログでないファイルは無視されます)。同じ対局が複数の場所にあっても1回だけ解析します。

## 使い方

リポジトリのルートで実行する例です。

```
# まず抽出される対局を確認する (解析はしない)
python src/tools/ggs_analyze/ggs_analyze.py bin/ggs/log/my_tournament --me my_account --vs rival_a --vs rival_b --list

# 解析する
python src/tools/ggs_analyze/ggs_analyze.py bin/ggs/log/my_tournament --me my_account --vs rival_a --vs rival_b
```

この例では、

- 負けたマッチ (相手は問わない)
- rival_a または rival_b と引き分けたマッチ

の対局をすべて解析します。解析中は1手ごとに結果と所要時間が表示されます。

終わると `bin/ggs/log/analyze/report.md` にレポートができます (出力先は `--out` で変更できます)。

解析済みの結果からレポートだけを作り直したいとき (スクリプトを更新してレポートの内容が増えたときなど) は、同じ抽出条件に `--report-only` を付けて実行します。エンジンは動かしません。

```
python src/tools/ggs_analyze/ggs_analyze.py bin/ggs/log/my_tournament --me my_account --vs rival_a --vs rival_b --report-only
```

### 途中で止める・再開する

解析結果は1手解析するごとに `出力先/cache/positions_*.jsonl` に書き込まれます (解析設定ごとに1ファイル)。1局が終わると、その局の結果も `出力先/cache/` に保存されます。Ctrl+C で止めたりエンジンが落ちたりしても、同じコマンドをもう一度実行すれば、解析済みの局面を飛ばして続きから再開します。`analyze` は棋譜の最後から逆順に解析するので、途中で止まった局は残りの序盤側だけを解析し直します。

キャッシュは「局面 + 打った手 + 解析設定」ごとなので、抽出条件を変えて実行し直しても、同じ設定で解析済みの局面は再利用されます。解析設定を変えると別物として解析し直します。キャッシュを使わずにやり直したいときは `--force` を付けます (以前の結果は消さずに、新しい結果を追記します)。

### 共通の序盤の流用

シンクロ対局の `.N.0` と `.N.1` は開始局面が同じなので、序盤の進行がしばらく同じになることがあります。そこで、同じ設定で解析済みの局面 (キャッシュにあるものを含む) と盤面・着手が同じ手は、その解析結果を流用し、まだ解析していない手だけを Egaroucid に解析させます。全ての手が解析済みなら Egaroucid は起動しません。`--jobs` で並列にしても、同じマッチの2局は同じエンジンで順番に解析するので流用が効きます。

流用した手は、実行中の表示とレポートの全着手の表 (時間の欄が「流用」) で分かります。`moves.csv` では `reused_from` 列に流用元の対局が入ります。

## 対局の抽出ルール

| オプション | 意味 |
|---|---|
| `--me NAME` | 自分のアカウント名。複数指定できます。省略するとスクリプト先頭の `DEFAULT_ME` を使います。 |
| `--vs NAME` | 負けに加えて、この相手との**引き分け**も抽出します。複数指定・カンマ区切り (`--vs rival_a,rival_b`) ができます。 |
| `--vs-only` | `--vs` で指定した相手との対局だけを抽出します (その相手への負けと引き分け)。 |
| `--draws` | 全ての相手との引き分けも抽出します。 |
| `--exclude NAME` | この相手との対局を除外します (例: 自分のテスト用アカウント)。 |
| `--unit match` / `--unit game` | 勝敗を判定する単位 (後述)。既定は `match`。 |
| `--since` / `--until` | 終局日時で絞り込みます。`2026-09-26` や `"2026-09-26 15:00"` の形式。終局日時はファイル名の日時です。 |
| `--max-games N` | 解析する対局数の上限 (古い順に N 局)。 |
| `--no-recursive` | ディレクトリのサブディレクトリを探しません。 |
| `--list` | 抽出結果を表示するだけで解析しません。 |

### マッチ単位 (`--unit match`、既定) と対局単位 (`--unit game`)

GGS の大会はシンクロ対局 (同じ開始局面を黒白入れ替えて2局打つ。ID は `.N.0` と `.N.1`) で、順位表の勝ち・負け・引き分けは **2局の合計石差** で決まります。1局ずつ見ると、ランダムな開始局面が片方の色に有利なため「マッチには勝ったが片方の局は負け」がよくあります。

- `--unit match` (既定): 2局の合計で勝敗を判定し、負け (または対象の引き分け) のマッチは **2局とも** 解析します。レポートの「マッチ一覧」で、2局それぞれの自分と相手の損失合計を比べられます。シンクロでない対局は1局で1マッチとして扱います。
- `--unit game`: 1局ごとの結果で判定します。

結果が記録されていない対局 (`black's score: -99`) と、自分同士の対局 (`--me` に両者が含まれる) は除外します。

## 解析設定

既定では次の設定で読みます。

| 空きマス数 | 探索 |
|---|---|
| 60〜44 | 中盤探索 深さ35 (MPC 74%) |
| 43〜41 | 終盤読み切り (MPC 88%) |
| 40〜38 | 終盤読み切り (MPC 93%) |
| 37〜35 | 終盤読み切り (MPC 98%) |
| 34〜31 | 終盤読み切り (MPC 99%) |
| 30〜1 | 完全読み (100%) |

オプションで変えられます。

| オプション | 既定 | 意味 |
|---|---|---|
| `--mid-depth` | 35 | 中盤探索の深さ |
| `--mid-prob` | 74 | 中盤探索の MPC 確率 |
| `--end-empties` | 43 | この空きマス数から終盤読み切りにする |
| `--exact-empties` | 30 | この空きマス数から完全読みにする |
| `--end-probs` | 88,93,98,99 | 終盤読み切りの区間 (`--end-empties` 〜 `--exact-empties`+1 空き) を前から均等に分けて使う MPC 確率 |
| `--book` | なし | book を使う。既定では book を使わず全局面を上の設定で探索します |
| `--threads` | 論理コア数 / `--jobs` | 1エンジンあたりのスレッド数 |
| `--jobs` | 1 | 同時に動かすエンジンの数。スレッド数を増やしても効率が落ちる場合は、`--jobs 2` などでマッチ単位で並列にすると速くなることがあります。メモリはエンジンの数だけ必要です |
| `--hash` | 29 | 置換表の大きさ (`-hash`)。29 だと1エンジンあたり約16GB (2^29 エントリ × 32 バイト) のメモリを使います。メモリが足りない場合は小さくしてください |
| `--engine-arg` | なし | エンジンに追加で渡す引数 (`--engine-arg=-seed --engine-arg=1` のように1つずつ指定) |
| `--mistake-threshold` | 4 | 悪手とみなす損失 (石数) |
| `--report-only` | なし | エンジンを動かさず、キャッシュ (解析済みの対局と1手ごとの結果) からレポートと CSV だけを作り直します。解析が終わっていない対局は「まだ解析していない対局」として一覧に出します |
| `--client-log` | 対局ログの場所から探す | 対局時の読みを取る GGS クライアントのログ (`*_ggs.log`) またはそのディレクトリ (後述) |

使われる確率は `74, 88, 93, 98, 99, 99.9, 100` のどれかです。contest book は使いません (`-nocontestbook`)。

設定は Egaroucid for Console の `-dpr <開始手数> <終了手数> <深さ> <確率>` に変換して渡しています (手数 = 61 − 空きマス数、終盤読み切りは深さ 60 で指定)。実際に使ったコマンドは実行時に表示されます。手で同じことをする場合は次のようになります。

```
bin/Egaroucid_for_Console_clang.exe -quiet -nobook -nocontestbook -hash 29 -dpr 1 17 35 74 -dpr 18 20 60 88 -dpr 21 23 60 93 -dpr 24 26 60 98 -dpr 27 30 60 99 -dpr 31 60 60 100
setboard <初期盤面>
play <棋譜>
analyze
```

### 所要時間の目安

深く読むので時間がかかります。既定の設定、28 スレッド 1 エンジンで大会の1局 (50手) を解析した例では、

| 区間 | 局面数 | 合計時間 | 1局面あたり |
|---|---:|---:|---|
| 完全読み (30〜1空き) | 30 | 約17秒 | 30空きで約9秒 |
| 終盤読み切り (43〜31空き) | 13 | 約16分 | 4秒〜4分 (空きが多いほど長い) |
| 中盤探索 深さ35 (44空き〜) | - | - | 44空きで約22秒 |

でした。時間の大半は終盤読み切りの区間 (特に 43〜37 空き) です。局面によって大きく変わります。

まず `--mid-depth 21 --end-empties 30 --exact-empties 24` のような軽い設定で全体を見て、気になる対局だけ既定の設定で解析し直すのもおすすめです (設定ごとにキャッシュされます)。

## 出力

出力先 (既定: `bin/ggs/log/analyze/`) に次のファイルができます。レポートと CSV は実行のたびに、その回に抽出した対局の内容で上書きされます。

| ファイル | 内容 |
|---|---|
| `report.md` | 解析レポート (Markdown) |
| `games.csv` | 1局1行の集計 |
| `moves.csv` | 1手1行の解析結果 (盤面文字列、打つ前の石数、対局時の読み・評価・思考時間つき) |
| `cache/` | 1局ごとの解析結果 (再開・再利用用の JSON) |

### report.md の内容

- **まとめ**: 自分と相手の悪手・疑問手の数、損失の合計と1手あたりの平均
- **石損したタイミング**: 自分の手の損失を、打つ前の石数別と対局時の読み (深さ@MPC確率) 別に集計した表と、石損した手の一覧 (損失の大きい順、石数・対局時の読み・対局時の評価・思考時間つき)
- **相手別**: 相手ごとの負け・引き分けマッチ数と損失
- **マッチ一覧** (`--unit match` のとき): 2局それぞれの結果と、自分・相手の損失合計
- **対局一覧**: 各局の結果、開始局面の評価、悪手・疑問手の数、敗着候補
- **対局詳細**: 各局について
  - 敗着候補 (または勝ちを逃した手の候補) と、損失が最大だった手の盤面図と盤面文字列
  - 自分の損失がある手の一覧 (石数・対局時の読み・思考時間つき)、相手の悪手の一覧
  - 全着手の解析 (折りたたみ)

盤面文字列 (`--OX...- X` の形式) はそのまま Egaroucid for Console の `setboard` に使えます。

### 用語

- **評価値**: 手番側から見た最終石差の予想 (空きマスは勝った側に加算)。
- **損失**: その局面での最善手の評価値 − 実際に打った手の評価値。打った手が最善なら 0。
- **悪手**: 損失が `--mistake-threshold` (既定 4) 以上の手。**疑問手**: 損失が 1〜3 の手。
- **区分悪化**: 打つ前は勝ち (評価 +) だったのに打った後は引き分け・負けになった、のように勝ち/引き分け/負けの区分が悪くなった手。
- **敗着候補**: 自分の手で最後に区分を悪化させた手。相手のミスでいったん区分が戻り、その後また悪化させた場合は後の方です。負けた局に表示します (引き分けの局では「勝ちを逃した手の候補」)。
- **開始局面評価**: 最初の局面を自分から見た評価値。GGS のランダム開始局面では開始時点で不利なことがあり、その場合は自分の手で区分が悪化していなくても負けます。
- **石数**: その手を打つ前の盤上の石の数。
- **対局時の読み**: GGS でその手を選んだときの探索の深さ@MPC確率 (例: `28@88%`)。深さが空きマス数以上なら終盤の読み切り、`100%` なら完全読みです。**解析の読み**はこのスクリプトで解析したときの深さ@確率です。

### 対局時の読みの取得

対局時の読み・評価・思考時間は、GGS クライアントのログ (`-ggslogdir` / `-ggslogfile` で出力される `*_ggs.log`) の `search ready` などの行から、対局 ID・盤面・着手で対応付けて取ります。ログは対局ログのディレクトリ (再帰的) とその親ディレクトリから探し、対局の終局時刻にそのセッション (ファイル名の開始時刻〜最終更新時刻) が動いていたものを使います。別の場所にある場合は `--client-log` で指定してください。対応付けられなかった手は「-」(集計では「不明」) になります。探索の深さが記録されていない古いログ (2026年6月頃まで) からは取れません。

### 注意

- 中盤探索と MPC つき終盤読み切りの評価値には誤差があります。特に中盤の 1〜2 石の損失は誤差の可能性があります。完全読みの区間 (既定では 30 空き以下) の評価値と損失は正確です。
- 時間切れ・投了などで終局前に終わった対局は棋譜の最後まで解析し、盤上の評価より結果が悪い場合はレポートに注意を表示します。
- 相手の手の損失も同じように計算しているので、相手が間違えたのに自分がそれを活かせなかった場所も分かります。
