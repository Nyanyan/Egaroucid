# accuracy_test

GGS の対局を深く解析した結果から、「どの手がどれだけの値か」が分かっている局面を集めたベンチマークです。評価関数や探索を変えたときに、浅い探索でよい手を選べるようになったかを測るために使います。

## ファイル

- `accuracy_test.jsonl`: 1行1局面。
  - `board`: 64文字（a1, b1, ..., h8 の順。`X` = 黒、`O` = 白、`-` = 空き）
  - `turn`: 手番（`X` か `O`）
  - `empties`: 空きマス数
  - `evals`: その局面を解析した結果のリスト。各要素は次のとおりです。
    - `depth`: 解析の深さと MPC の確率（例: `36@88%`。`@100%` は完全読み）
    - `values`: 解析した手と、その手の値（手番側から見た最終石差の予想）。同じ要素の中の値どうしは、同じ設定で探索したので比べられます。
    - `best`: 全ての手を探索した解析なら、記録された手の中で値が一番高い手。2つの手だけを比べた解析では `null`。
    - `kind`: `ggs_analyze`（GGS 解析ツールの結果）、`divergence_ref`（2026-10-10 の分岐局面の参照値）、`schedule_ref`（2026-09-29 の時間配分比較の参照値）
    - `source`: 元のデータ

## 作り方と使い方

- 作り直し: `python src/tools/accuracy_test/build_accuracy_test.py`（リポジトリ内の解析結果を集めます）
- 採点: `python src/tools/accuracy_test/accuracy_test.py --engine bin/<実行ファイル> --min-empties 30 --out <出力先> -- -l 11 -thread 1`
  - エンジンに全局面を `-solve` で解かせ、選んだ手を次の3つに分けて数えます。
    - 最善手と一致
    - 値が分かっている別の手（損失 = 最善手の値 − 選んだ手の値）
    - 値が分かっていない手

## 注意

- 参照値は今の Egaroucid（今の評価関数）による深い探索の値です。新しい評価関数が参照と違う手を選んだとき、それが本当に悪い手とは限りません。
- `ggs_analyze` の記録では、制限なしの探索が選んだ手（alt）の値が、打った手の値より低いことがよくあります（探索の揺れ）。そのため、記録された手の中で値が一番高い手を最善手としています。
- GGS 由来なので、同じ対局から似た局面が続けて入っています。信頼区間は対局単位で考えてください。
